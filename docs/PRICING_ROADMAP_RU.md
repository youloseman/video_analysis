# ЧАСТЬ 1. Runbook: что сделать руками прямо сейчас

Шесть шагов, порядок важен. Всё в **test mode** — реальные деньги не двигаются.

## Шаг 1. Создать цены в Stripe (~10 минут)

Stripe Dashboard → **Product catalogue** → для каждого продукта добавить цену. **Валюта у всех — USD.**

| Продукт | Цена | Тип | Переменная окружения |
|---|---|---|---|
| Flapp Enthusiast | **$9.00** | Recurring · Monthly | `STRIPE_PRICE_ENTHUSIAST_M` |
| Flapp Enthusiast | **$69.00** | Recurring · Yearly | `STRIPE_PRICE_ENTHUSIAST_Y` |
| Flapp Full | **$99.00** | Recurring · Yearly | `STRIPE_PRICE_FULL_Y` |
| Expert Review | **$39.00** | One-time | `STRIPE_PRICE_EXPERT` |
| Unlock one report | **$4.00** | One-time | `STRIPE_PRICE_UNLOCK` |

Скопировать id каждой цены (вид `price_1Abc...`) — это **id цены, не продукта**. Самая частая ошибка здесь: скопировать `prod_...`.

Про `STRIPE_PRICE_UNLOCK`: цена создаётся заранее, но продукт ещё не продаётся — ключ `unlock` намеренно отсутствует в `plan_price_map` ([config.py](../backend/app/core/config.py)), иначе checkout принял бы оплату за разблокировку, которую вебхук не умеет применять. Подключится в Фазе 2.

**Старые цены** ($59 / $80 / $29) — **архивировать, не удалять**. Удаление ломает ссылки в истории платежей; архивная цена просто перестаёт предлагаться.

## Шаг 2. Обновить переменные на Railway (~2 минуты)

Railway → сервис → **Variables** → вписать пять id из шага 1.

Учтите: изменение переменных само по себе перезапускает сервис — на короткое время задеплоенный старый код будет работать с новыми ценами (покажет $59, спишет $69). В тестовом режиме это никого не касается; когда пойдёте в live, шаги 2 и 3 надо делать подряд.

## Шаг 3. Подключить том (~5 минут) — обязательно

Railway → сервис → **Settings → Volumes** → создать том, точка монтирования **`/data`**.
Затем в **Variables**: `VA_UPLOADS_DIR=/data/uploads`.

Без тома файловая система контейнера эфемерна: клипы исчезают на следующем же
деплое, и это ломает сразу два обещания — политика приватности говорит, что
footage хранится фиксированный срок, а Expert Review продаётся как «человек
посмотрит ваше видео». Ошибки при этом не будет ни одной.

Размер: считайте ~25 МБ на разбор (клип плюс оверлей) × 30 дней оборота. На
старте достаточно 5–10 ГБ.

## Шаг 4. Запушить код

```
git push origin main
```

Пуш в `main` автоматически деплоит на Railway. Локально готовы `25dfa95` (цены) и `25ccf8e` (хранение).

## Шаг 5. Проверить лог деплоя

В логе Railway должно появиться:

```
BILLING_READY  plans=['enthusiast_monthly','enthusiast_yearly','expert','full_yearly']
BILLING_TEST_MODE  detail=Stripe key is a TEST key -- live cards will be declined
MIGRATED  change=users.expert_credits added + granted to full
MIGRATED  change=users.expert_credit_grant_ref added
MIGRATED  change=analyses.job_id added
DB_READY
SWEEP_STARTUP  dirs_deleted=0 retained=0
```

- **`BILLING_READY` с четырьмя планами** — это норма, не ошибка. `unlock` в этом списке появится только в Фазе 2.
- **`BILLING_PRICES_MISSING`** — какой-то id не проставлен. Именно этот случай раньше был невидим: на странице просто оказывалась мёртвая кнопка. Теперь она честно скажет «Coming soon», но чинить всё равно надо.
- **`BILLING_TEST_MODE`** — ожидаемо, тестовый ключ стоит намеренно.
- **`MIGRATED ... expert_credits`** — миграция выполняется на старте, отдельно запускать ничего не нужно. Она же выдаёт кредит всем, кто уже на тарифе Full: они оплатили период, в который ревью входило, но механизма выдачи тогда не существовало.

## Шаг 6. Проверить руками (~10 минут)

**Страницы:**

| Где | Что должно быть |
|---|---|
| `/` (лендинг) | $0 / $69 / $99, карточка Expert Review $39, футер «Prices in USD» |
| `/terms` | Таблица с новыми ценами, «**US dollars (USD)**», раздел про включённые ревью |
| `/app` → Pricing | Переключатель Monthly/Yearly, бейдж «save ~36%» |
| `/app` → Pricing → **Monthly** | Full показывает $99 и подпись «annual only · no monthly option» |
| `/billing/plans` | JSON, у всех цен `"available": true` |

**Сквозной сценарий покупки** (тестовая карта `4242 4242 4242 4242`, любой будущий срок и CVC):

1. Купить **Full** → после вебхука тир становится `full`.
2. Открыть Pricing → карточка Expert Review показывает **«Included»** и кнопку **«Use your included review»** вместо цены.
3. Нажать → выбрать разбор → в модалке должно быть «Expert Review · included with your plan» и кнопка **«Use my included review»** (не «Continue to payment»).
4. Подтвердить → тоста «Booked with the Expert Review included in your plan».
5. Открыть `/app` под админом → очередь заказов: заказ с планом `expert_credit`, суммой **$0**.
6. Вернуться на Pricing → карточка снова продаёт за $39 (кредит потрачен).

**Настроить портал Stripe** — Settings → Billing → **Customer portal**:
- разрешить **смену плана** между тремя подписочными ценами;
- разрешить **отмену**.

Без этого апгрейд Enthusiast → Full упирается в портал, где переключиться некуда: сервер намеренно отправляет туда вместо второго checkout, иначе на карте оказались бы две подписки сразу.

## Откат, если что-то не так

```
git revert 25ccf8e 25dfa95 && git push origin main
```

И **вернуть старые id цен** в переменных Railway. Только код без отката переменных даст обратную рассинхронизацию: страница покажет $59, а спишет $69.

Том при откате **не отключайте**: колонка `analyses.job_id` останется (миграции только добавляют), а лишний том никому не мешает. Отключение тома — это потеря уже сохранённых клипов.

# ЧАСТЬ 2. Что уже сделано в Фазе 0

Коммит `25dfa95`. 296 тестов проходят, ruff чист.

### Единый каталог цен

Новый [services/pricing.py](../backend/app/services/pricing.py) — единственное место, где записана сумма. Потребители:

- **Приложение** — `GET /billing/plans`, карточки рендерятся из JSON ([billing.py](../backend/app/api/billing.py))
- **Лендинг** — токен `<!--PRICING-->` подставляется в оболочку при отдаче ([main.py](../backend/app/main.py))
- **Оферта** — токен `<!--PLANS-TABLE-->`, роут `/terms` теперь рендерит, а не отдаёт файл
- **Проза** — токен `<!--EXPERT-PRICE-->` для упоминания цены в тексте лендинга

Скидка за год не записана, а **вычисляется** из месячной и годовой цены — бейдж на переключателе и подпись под ценой были двумя копиями одного утверждения.

Тест сканирует все три документа регуляркой и падает, если кто-то впишет цену руками. Он же поймал `from <b>$9</b>/mo` на панели апселла, которая пряталась внутри тега.

### Валюта

Оферта обещала канадские доллары, футер — американские. Теперь USD везде + абзац о том, что делает банк, если карта выпущена в другой валюте.

### Кредит Expert Review

`users.expert_credits` + `users.expert_credit_grant_ref`.

- **Начисление** привязано к платежу, а не к тиру: админу биллинг тир не меняет, но купленное он получить обязан. `expert_credit_grant_ref` хранит id объекта Stripe, который последним пополнил баланс — иначе повторная доставка вебхука начисляла бы кредит на каждую попытку.
- **Списание** не идёт в Stripe вообще. Checkout-сессия на $0 всё равно спрашивает карту — странная просьба к человеку, который оплатил это год назад.
- **Двойной клик** ловится уникальным индексом `orders.stripe_session_id` (ключ вида `credit:<user>:<analysis>`), а не проверкой-перед-вставкой, которая проигрывает гонке.
- **Отмена подписки кредит не забирает** — период оплачен.
- Списание требует выбранного разбора: платный путь переживает его отсутствие (рецензент выберет клип в очереди), а кредит тратится необратимо.

### Правда на карточках

С Full сняты три обещания без кода: multi-bike профили, фирменный PDF, сравнение между профилями. Останутся снятыми до Фазы 3. Starter признал облачную историю, которую и так отдавал (`/me` никогда не проверял тир).

### Прочее

Admin 10/день. Expert Review — карточка во всю ширину под сеткой (четвёртая колонка в контейнере 1000px оставляет по 220px — нечитаемо). Панель апселла и модалка выбора разбора берут цену из каталога.

### Известный пробел

**Начисление кредита на автопродлении не работает.** Stripe сообщает о продлении событием `invoice.payment_succeeded`, которое вебхук не слушает. Первое продление — через год. Зафиксировано в комментарии у места начисления и в Фазе 3 ниже.

## Фаза 2 — Превью + Unlock за $4 · размер L · 3–4 дня

Главный рычаг конверсии. Содержит архитектурную развилку.

### Развилка: резать на чтении, а не на записи

Сейчас `gate_free_result` вырезает платные поля **до сохранения**, и в историю ложится уже урезанный результат. Полный живёт только в памяти job-store 6 часов. Значит, разблокировать за $4 **физически нечего**.

```
Было:  анализ → обрезать → сохранить обрезанное → отдать
Стало: анализ → сохранить полностью → обрезать по правам → отдать
```

Побочный эффект оправдывает работу сам по себе: **апгрейд открывает всю прошлую историю**. Сегодня это невозможно в принципе, а как аргумент к покупке — сильнее самой кнопки $4.

Цена: полные результаты бесплатных пользователей ложатся в БД (~30–80 КБ JSON), и это надо отразить в политике приватности.

## Открытые вопросы

1. **Блюрить ли «Key metrics» в превью** — сейчас оставлен видимым: без него Coach's notes ссылаются на числа, которых человек не видит.
2. **Сколько слотов Expert Review в неделю** вы готовы отдавать при ~40 минутах на разбор.
3. **Что с существующими аккаунтами** при запуске превью: считать израсходованным или подарить всем как повод вернуться. Я бы подарил — это письмо «мы открыли вам полный разбор», а не тихое изменение правил.
4. **Нужна ли четвёртая колонка** вместо карточки Expert Review во всю ширину (см. Фазу 0).
