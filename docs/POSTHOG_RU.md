# PostHog: аналитика продукта

_Составлено 20.08.2026. Код: `backend/app/services/analytics.py`._

Что было до этого: сервер знает, что клип проанализирован, и не знает, закрыл ли
человек вкладку сразу после. Все вопросы вида «сколько дошло от лендинга до
первого анализа», «сколько увидело пейволл и открыло цены», «на каком шаге
отваливаются» отвечались догадками.

Аналитика **выключена, пока не выставлен `POSTHOG_KEY`**. Без ключа сниппет не
вставляется ни в одну страницу, сервер не отправляет ни одного события, и
политика конфиденциальности честно пишет «аналитики нет» — раздел 7 в
`privacy.html` существует в двух вариантах, сервер оставляет верный.

---

## 1. Создать проект (~5 минут)

1. [posthog.com](https://posthog.com) → Sign up. Бесплатный тариф: 1 млн событий
   в месяц — для текущего трафика это с большим запасом.
2. **Регион**: US или EU. Данные останутся там навсегда — переехать между
   регионами нельзя, только начать заново. Clariva в Канаде, аудитория —
   Северная Америка: **US Cloud** (`https://us.i.posthog.com`) логичнее.
   Если приоритет — GDPR-аудитория из Европы, брать EU.
3. Project name: `Flapp`.
4. При онбординге спросят про установку сниппета — **пропустить**, он уже в коде.
5. Скопировать **Project API key** (`phc_…`): Settings → Project → Project API key.

Ключ **публичный** — он лежит в исходнике страницы, так и задумано. Секретный —
это Personal API key, приложение его не использует и он не нужен.

## 2. Railway: переменные

| Переменная | Значение | Обязательна |
|---|---|---|
| `POSTHOG_KEY` | `phc_…` из шага 1 | да, иначе всё выключено |
| `POSTHOG_HOST` | `https://us.i.posthog.com` (или `https://eu.i.posthog.com`) | нет, US по умолчанию |
| `POSTHOG_SESSION_RECORDING` | `0` | нет, по умолчанию выключено |

Регион в `POSTHOG_HOST` должен совпадать с регионом проекта, иначе события
уходят в пустоту без единой ошибки в логе.

После деплоя в логе Railway должно быть:

```
ANALYTICS_READY  host=https://us.i.posthog.com  session_recording=False
```

Если видно `ANALYTICS_DISABLED` — ключ не подхватился.

## 3. Что настроить внутри PostHog (обязательно)

Это не косметика — на два пункта из трёх ссылается опубликованная политика
конфиденциальности.

1. **Data retention → 12 месяцев.** Settings → Project → Data management.
   Политика (раздел 10) обещает «до 12 месяцев». По умолчанию PostHog хранит
   дольше — обещание нужно привести в исполнение, а не оставить на бумаге.
2. **Session replay — оставить выключенным.** Политика прямо пишет «Session
   replay is off». Если когда-нибудь включать (`POSTHOG_SESSION_RECORDING=1`) —
   сначала правится раздел 7 `privacy.html`, потом переменная. Причина
   осторожности не юридическая: реплей пишет DOM, а на странице результата в DOM
   лежит видео самого спортсмена.
3. **Anonymize IPs** (Settings → Project) — по вкусу. Без этого PostHog
   определяет страну/город по IP; политика это раскрывает.

## 4. Что именно отправляется

Ничего из клипа, ни имени файла, ни текста, который человек напечатал.

### Из браузера

| Событие | Когда | Ключевые свойства |
|---|---|---|
| `$pageview` | загрузка любой страницы (лендинг, `/app`, Academy, юридические) | стандартные |
| `view_opened` | переход между экранами внутри SPA | `view` |
| `landing_cta_clicked` | клик по любой ссылке на `/app` с лендинга | `cta`, `section`, `to_signup` |
| `landing_section_viewed` | секция лендинга доскроллена | `section` |
| `signed_up` / `logged_in` / `logged_out` | вход/регистрация | `pending_analysis` |
| `analysis_started` | нажат «Analyze» | `mode`, `sport`, `position`, `file_mb`, `duration_s`, `tier` |
| `analysis_completed` | результат отрисован | `score`, `grade`, `gated`, `locked`, `seconds`, `tier` |
| `analysis_failed` | анализ упал | `reason` (наш текст ошибки), `counted` |
| `limit_reached` | упёрлись в лимит тарифа | `tier`, `signed_in` |
| `paywall_shown` | показан заблокированный блок | `reason`, `where`, `sellable` |
| `checkout_needs_account` | нажали купить без аккаунта | `plan` |
| `checkout_started` | пошли в Stripe Checkout | `plan`, `period` |
| `checkout_returned` | вернулись из Stripe | `result` (success/cancel) |
| `ai_export` | выгрузка анализа для ChatGPT | `how`, `format` |
| `share_card_built` | собрана картинка для Strava/Instagram | `sport`, `score` |
| `result_feedback` | отправлен фидбек по результату | `rating`, `tags` (количество) — **без текста** |

### С сервера (вебхук Stripe)

| Событие | Когда | Свойства |
|---|---|---|
| `purchase_completed` | Stripe подтвердил платёж | `plan`, `tier`, `kind`, `revenue`, `currency` |
| `subscription_renewed` | продление подписки | `tier`, `revenue`, `currency` |
| `subscription_canceled` | подписка закрыта | — |

Деньги считаются **только с сервера**: `checkout_returned` из браузера
срабатывает лишь если вкладка пережила редирект, а списание проходит в любом
случае. Один и тот же человек: браузер делает `identify(analytics_id)`, сервер
шлёт события под тем же id (`u<id>` из БД, см. `analytics.person_id`).

## 5. Первые три вопроса, ради которых всё это

Создать в PostHog → Insights → Funnel:

1. **Лендинг → анализ.** `$pageview` (url = `/`) → `landing_cta_clicked` →
   `signed_up` → `analysis_started` → `analysis_completed`.
   Здесь видно, что дороже: регистрация до анализа или сам анализ.
2. **Пейволл → деньги.** `paywall_shown` → `view_opened` (view = `pricing`) →
   `checkout_started` → `purchase_completed`.
   Разрыв между `checkout_started` и `purchase_completed` — это форма оплаты;
   разрыв раньше — это цена или само предложение.
3. **Качество анализа.** Trends: `analysis_failed` с разбивкой по `reason`,
   рядом `analysis_completed` с разбивкой по `gated`. Сколько людей платят
   вниманием за результат, в котором мы сами не уверены.

Ретеншен: Retention → возвращаются ли после `analysis_completed`. Для продукта,
который живёт на подписке, это более важное число, чем весь верх воронки.

## 6. Блокировщики рекламы

uBlock и подобные режут запросы к `*.posthog.com` — на аудитории велосипедистов
это заметная доля. Часть событий просто не дойдёт, и это будет выглядеть как
провал в воронке, а не как блокировка.

Лечится реверс-прокси на своём домене: поднять `https://getflapp.com/ph` →
PostHog и выставить `POSTHOG_HOST=https://getflapp.com/ph`. Код это уже
поддерживает: библиотека тогда грузится с того же хоста
(`_assets_host` в `analytics.py`), а не с `us-assets.i.posthog.com`.
Отдельная задача — сейчас не сделано.

## 7. Отказ от аналитики

- Браузер с **Do Not Track** — не собирается ничего (`respect_dnt: true`).
- На `/privacy`, раздел 7 — кнопка «Turn off analytics on this device».
- Удаление аккаунта: события в PostHog **не удаляются автоматически**. Если
  придёт запрос на удаление — PostHog → Persons → найти `u<id>` → Delete.
  Политика это обещает («deleted on request, or when you delete your account»),
  и пока это ручная операция.

## 8. Проверка после деплоя

1. Открыть `/` в обычном окне → PostHog → Activity: должен появиться `$pageview`
   в течение минуты.
2. Пройти путь: лендинг → регистрация → анализ. Ожидаются `landing_cta_clicked`,
   `signed_up`, `analysis_started`, `analysis_completed`, и все — под одним
   человеком с email в свойствах.
3. Открыть `/privacy` → раздел 7 называет PostHog, кнопка отключения работает
   (после нажатия текст меняется на «Turn analytics back on»).
4. Тестовая покупка (см. `STRIPE_GO_LIVE_RU.md`, раздел 8) → в PostHog должен
   прийти `purchase_completed` с `revenue`, **от сервера**, а не из браузера.

Если событий нет: смотреть консоль браузера (заблокирован ли `array.js`),
затем регион в `POSTHOG_HOST`, затем лог Railway на `ANALYTICS_READY`.
