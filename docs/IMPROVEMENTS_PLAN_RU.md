# План улучшений Flapp — ближайшее время

Дата: 2026-08-21. Источники: [конкурентный анализ](https://claude.ai/code/artifact/9439be1c-b455-4eb9-9aee-e3a57883fe75)
(Ochy, MyVeloFit, BikeFit-IA, Movaia, Runmatic, Velogicfit, Kinovea, Dartfish) +
утверждённый Kinovea-план (B→A→C→D→F; B-кинограмма готова) + эксперимент с кадрированием
(leg_swap 45.6% → 1.8% на том же клипе — кадрирование, а не детектор, ломает метрики).

**Принципы порядка:**
1. Сначала фичи и точность, **мобильные приложения — последними** (решение Артура).
2. Каждая фича сохраняет «инженерию честности» — это наш главный дифференциатор.
3. Сначала то, что усиливает уже оплаченные разрывы (вело-паритет, точность), потом новые плоскости (вид сзади).

**Позиционирование, которое всё это обслуживает:** единственное приложение «бег + вело»
для триатлета, честное про пределы измерений, с aero-анализом и человеческим ревью.

**UI/UX-работы вынесены в отдельный план** — `docs/DESIGN_PLAN_RU.md` (первый экран,
дефект-волна, визуальный гид съёмки, соц-логин, чат-коуч, токены → тёмная тема);
пересечения с фазами ниже помечены в нём.

## Фаза 1 — Точность измерений (1–2 недели)

Порядок внутри фазы — по доказанному эффекту, а не по алфавиту Kinovea-плана:
F идёт первым (см. эксперимент с кадрированием).

| # | Задача | Зачем |
|---|--------|-------|
| 1.1 | **F — Гид по съёмке** (pre-upload экран + страница): вертикально, атлет ~2/3 высоты кадра, сбоку строго перпендикулярно, 60fps/slow-mo, короткая выдержка | Доказанный рычаг ×25 по качеству трекинга; ничто другое не даёт столько за день работы |
| 1.2 | Снять эталонные клипы (Артур): чистый бег 6–10 с по гиду 1.1 (+ вело для регрессии) | В репо нет ни одного пригодного бегового клипа; без него MVP/Strike кинограммы и GCT не валидируются |
| 1.3 | **Slow-mo протокол для GCT/flight**: slow-mo уже детектится для каденса — распространить выгоду на временные метрики, отразить в confidence | Movaia продаёт «4× точность» ровно на этом; наш шаг 33 мс на 30fps — честная слабость |
| 1.4 | **A — Авто-cutoff Butterworth** (Winter residual analysis, per-angle, с фолбэком и физиологическим клампом) | Kinovea-план; убирает произвол фиксированных частот |
| 1.5 | **C — Угловые скорости как метрики** (уже считаются в phase_portrait, публикуем) | Kinovea-план; бесплатная глубина для продвинутых и Expert Review |
| 1.6 | **D — Масштаб от роста пользователя** вместо торса 0.45 м | ±15% систематики на VOSC/overstride; поле роста — один инпут |

## Фаза 3 — Вид сзади для бега (4+ недель, после Фазы 1)

Pelvic drop, пронация, валгус колена, step separation. Ранее осознанно выброшено из
роадмапа («дорого за 2 метрики») — **вернуть**: с 2026 это стандарт сегмента (Ochy делает
даже без дорожки, Movaia и RunForm AI — тоже), и именно в этой плоскости живёт
травматология бега. `RUNNING_REAR_VIEW_CONFIG` и quality-gate профиль `run_rear` в коде
уже есть. Начинать только после Фазы 1: вид сзади ещё чувствительнее к кадрированию.

## Чего сознательно НЕ делаем

- «Поинты»/кредиты в ценах (главный источник ненависти в отзывах Ochy).
- Геймифицированный «стиль бегуна» без тренировочной ценности.
- Мультиспорт-распыление а-ля SportsReflector (22 спорта = ни одного).
- Обещания абсолютного CdA (наш aero — честно относительный).
- Template-matching, chessboard/perspective калибровка, ручные инструменты (из Kinovea-анализа: смысл Flapp — чтобы они были не нужны).
- Переписывание `detect_gait_phase` — доказано, что проблема была в кадрировании, не в детекторе.
