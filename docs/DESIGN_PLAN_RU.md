Дата: 2026-08-21. Основа: [дизайн-аудит против конкурентов](https://claude.ai/code/artifact/7fe75b47-376c-4529-9cea-c0bc7e2704e2)
(скриншоты прода и 5 конкурентов + инвентаризация UI-кода + CSS конкурентов).
Продуктовый план — `docs/IMPROVEMENTS_PLAN_RU.md`; пересечения помечены.

**Принципы:** айдентику не трогаем (navy + Archivo italic + коралл — различимость);
«инженерию честности» сохраняем в каждом изменении; токены сводим к одному источнику
по ходу работ, а не отдельным мегапроектом в конце.

## 1. Первый экран приложения: инструмент вместо слогана

**Проблема.** `.hero` (градиент navy→blue, h1 «Train smart, move fast», диагональные
полосы `::after`) занимает ~280px лучшего пространства `/app`; на ноутбуке 1366×768
дропзона частично под фолдом, на телефоне — целиком. Слоган generic и не работает:
пользователь пришёл загружать клип. Лидеры (MyVeloFit, BikeFit-IA) открываются
сразу процессом.

**Решение.**
1. **Аноним / незалогинен:** полный `.hero` заменить на компактный хиро-стрип
   (~72–88px): одна строка ценности («Film 10 seconds — get every joint angle,
   a 0–100 score and a fix-first plan») + мини-строка доверия (mono, 12px:
   «SIDE-VIEW VIDEO OR PHOTO · RESULTS IN ~60 S»). Градиент и спидлайн оставить —
   это бренд, режем только высоту и убираем пустой слоган.
2. **Залогинен:** хиро-стрип не показывать вовсе (у него уже есть Home/дашборд;
   `body.authed` в разметке есть — условие готово).
3. **Компактнее селекторы:** спорт-тайлы `.tilerow` — добавить иконки бег/вело
   (спрайт `#i-*` уже есть) и уменьшить высоту; группы позиций `.posgroup`
   на мобиле — сетка 2 колонки вместо full-width стека (медиа-правило 560px).
4. **Цель-инвариант:** дропзона `.drop` полностью видима без скролла
   на 1366×768 (desktop, сайдбар 244px учтён) и на 390×844 (после хиро-стрипа
   и селекторов виден хотя бы верх дропзоны + подпись).

**Код:** `index.html` — секция `.hero` в `data-state="upload"`, CSS `.hero`
(строки ~650), `.tilerow`/`.tile-btn`/`.posgroup` + медиа 640/560. JS не меняется
(состояния/фокус не затронуты).

**Приёмка:** Playwright-скрины 1366×768 и 390×844 — дропзона в кадре; `#hint`
и quota-line не съехали; фокус-порядок прежний.

## 3. Визуальный гид по съёмке в дропзоне

Связка: продуктовый план Фаза 1.1 (capture guidance = доказанный рычаг ×25 к качеству
трекинга; кадрирование, не детектор, ломает метрики). Категорийный факт: гид по
съёмке — точка отказа №1 у всех конкурентов (главная жалоба RunForm, тихие фейлы Ochy).

**Решение.**
1. В пустой дропзоне `.drop` — **инлайн-SVG-иллюстрация** вместо голой иконки:
   вертикальная рамка телефона, силуэт атлета на ~2/3 высоты кадра, камера сбоку.
   Один взгляд = три правила.
2. `.guides` (7 текстовых пунктов) переработать: **3 главных — визуально**
   (вертикально · заполни кадр · строго сбоку), остальные 4 — в `<details>`
   «More tips». Добавить успокаивающую строку в тоне Movaia: «Don't overthink it —
   phone leaning on a water bottle works».
3. Preflight-сообщения (`checkClip()`) связать с гидом: к предупреждению —
   мини-ссылка «см. пример кадра» (скролл к иллюстрации).
4. Пост-анализный `.caprep` уже показывает framing-вердикт — в текст «tiny/small»
   добавить ту же отсылку к иллюстрации.
5. Slow-mo/60fps рекомендация (продуктовый план 1.3) — строкой в гиде, когда
   бэкенд начнёт тянуть из неё выгоду для GCT.

**Код:** `index.html` — `.drop`, `.guides`, `checkClip()`, `.caprep`-рендер.
Иллюстрация — инлайн SVG в спрайт (2 варианта: run/bike по выбранному спорту).

**Приёмка:** юзабилити-проверка «3 правила без чтения»; скриншот-регрессия;
(позже — метрика: доля анализов с framing=tiny должна падать, PostHog).

## 5. Соц-логин (Google, потом Apple)

Стена регистрации — главный конверсионный экран; сейчас на нём только email+пароль.
У Movaia/RunForm/MyVeloFit — Google и Apple.

1. **Google Identity Services** (бесплатно): кнопка в `#authModal` над полями,
   бэкенд `POST /auth/oauth/google` (верификация id_token, matching по email,
   создание юзера без пароля, обычный JWT). `pendingAnalyze`-резюме работает
   без изменений (авторизация завершает `submitAuth`-путь).
2. **Apple** — отложить: требует Apple Developer Program ($99/год). Решение за
   Артуром; станет обязательным при выходе в App Store (последняя фаза), тогда и делать.
3. Дизайн кнопок — по брендгайдам провайдеров (не перекрашивать под коралл).
4. Учесть в `DELETE /auth/account` (пользователи без пароля — подтверждение
   через повторный OAuth или email-код вместо пароля).

**Приёмка:** регистрация в 1 клик → анализ продолжается; повторный вход тем же
Google-аккаунтом попадает в тот же профиль; тесты на связку email.

## 7. Сдержанность аннотаций оверлея

Ochy ругают за «annotation overload»; Movaia аннотирует только ключевые моменты.
Наш materiality floor уже знает, что важно — оверлей должен знать то же.

1. `video_visualizer.py`: режим `annotation_level="material"` (default) — чипы
   углов рисуются только для метрик со статусом warn/bad или входящих в
   top-приоритеты плана; остальные суставы — скелет + маленькие точки без чипов.
   Режим `"all"` — текущее поведение.
2. UI-переключатель на плеере: «Only what matters / All angles»
   (localStorage, паттерн `.seg`).
3. Кинограмму и keyframe не трогать (там аннотации по месту).
4. Free-тизер не меняется (у него числа и так замаскированы).

**Приёмка:** на эталонном клипе с 2 проблемами оверлей показывает 2 чипа, не 8;
переключатель работает; тесты рендера обоих режимов.

## 10. AI-чат по отчёту (после волны конверсии)

Table stakes 2025–26 (RunBot, Coach IA). Вся инфраструктура готова:
Gemini-пайплайн, `build_metrics_block`, AI Export как модель контекста.
Первый шаг — free-text фокус-запрос (продуктовый план 0.4), чат его переиспользует.

1. **MVP:** панель чата на экране результата (под коуч-блоком). Контекст =
   metrics block + training_plan + confidence + блок «Not measured — do not infer»
   из `ai_export.py`. System-prompt наследует правила коуча: materiality floor,
   trade-offs, запрет выдумывать неизмеренное.
2. **Quick-reply чипы** из detected issues («How do I fix overstriding?»,
   «Knee pain — related?») — паттерн BikeFit-IA.
3. **Квоты:** платные тиры — N сообщений/анализ (стартово 10), free — 0
   (чат в `UNLOCK_COPY` как пункт апселла); rate limit + max tokens.
4. **Границы:** контекст только собственного анализа; никаких медицинских
   диагнозов (дисклеймер как у medical warnings).
5. UI: пузыри в бренд-стиле, mono для цифр, «Coach is typing…», ошибки — как
   `.cmp-ai-err` (грациозная деградация в статический коуч-текст).

## 12. Инфраструктура: один источник токенов → тёмная тема

Предпосылка любого будущего редизайна. Сейчас 4 копии токенов
(index.html / landing.html / academy renderer.py / brandbook-v2.html) уже разошлись.

1. **`static/tokens.css`** — единственный источник: цвета (включая st-шкалу,
   `--c-coral-btn`, `--c-media-bg`), шрифт-стек, радиусы, тени, ring.
   Подключить `<link>` в index/landing; renderer.py — инжектит содержимое файла
   (SSR без лишнего запроса). Удалить локальные копии, оставив странице только
   её специфику (лендингу — его радиусы через переопределение).
2. **Обновить brandbook-v2.html** под реальность: зелёно-янтарно-красная
   st-семантика (вместо «зелёного в системе нет»), coral-btn, грейд-шкала,
   min-height 44 как правило кнопок.
3. **Тёмная тема** — только после 1–2: `prefers-color-scheme` +
   `[data-theme]`-переключатель, переопределяются только токены;
   `color-scheme: light dark`; медиа-подложка и share-карточка остаются
   тёмными всегда (уже дизайн-решение). Оверлей-видео не трогаем.
4. Заодно: свести `.modetabs`/`.seg` в один компонент; единая шкала
   брейкпоинтов (900/640 + 380 по необходимости) при следующем большом
   заходе в CSS — не отдельным рефакторингом.
